# 01. 요구사항지시서

**프로젝트명:** 전남대학교 학생 정보·성적관리 데이터베이스  
**과목:** 데이터베이스 시스템 기말 프로젝트  
**작성일:** 2026-06-05  
**DBMS:** MySQL 8.0 / InnoDB / MySQL Workbench  
**데이터 출처:** 전남대학교 공식 대표 홈페이지 공개 대학·학부(과) 정보 + 개인정보를 포함하지 않는 임의 생성 학사 데이터

---

## 1. 문서 목적 및 범위

### 1.1 배경

본 문서는 전남대학교의 학생 정보와 성적을 관리하는 학사행정 DB의 요구사항 지시서이다.
해당 DB는 단순히 “전남대학교와 관련된 모든 정보”를 저장하는 범용 DB가 아니라, 학과 행정실과
학사관리 담당자가 학생의 소속 학과, 지도교수, 개설 강의, 수강신청, 성적 정보를 일관성 있게 관리하기
위한 학교 업무 DB로 정의한다.

기본 업무 데이터는 학생·학과·교수·강의·수강신청·성적으로 구성하며, 실제 전남대학교 환경과의
연결성을 높이기 위해 전남대학교 공식 대표 홈페이지에 공개된 학과명, 단과대학명, 학과 전화번호
114건을 `Dept` 데이터에 반영하였다. 다만 실제 학생 개인정보, 실제 학번, 실제 수강신청 내역,
실제 성적은 공개 데이터가 아니므로 사용하지 않고, 성능 실험에는 개인정보를 포함하지 않는 CSV
더미 데이터를 사용한다.

### 1.2 목적

1. 전남대학교의 학생 정보·수강신청·성적관리 업무를 개념적으로 모델링한다.
2. 개념적 모델을 관계 데이터 모델로 변환하고 BCNF 수준까지 정규화하여 중복과 이상 현상을 제거한다.
3. MySQL 8.0 기반으로 테이블, 기본키, 외래키, UNIQUE, CHECK, ENUM 제약을 구현하여 참조 무결성을 보장한다.
4. 전남대학교 공식 공개 학과 데이터를 반영하여 단순 예제 DB가 아니라 실제 학교 공개 정보와 연결된 학사관리 DB로 고도화한다.
5. View, Stored Procedure, Transaction, Index를 구현하여 학생 성적 조회, 공식 학과 조회, 원자적 데이터 처리, 검색 최적화를 제공한다.
6. 학생 10,000행, 강의 1,000행, 수강신청 50,000행, 성적 50,000행의 CSV 더미 데이터를 생성·적재하여 인덱스 적용 전후 성능을 정량적으로 비교한다.

### 1.3 시스템 범위

- 전남대학교 공식 공개 학과명, 단과대학명, 학과 전화번호 관리
- 학과, 교수, 학생의 기본 정보 관리
- 학기별 강의 개설 및 담당 교수 배정
- 학생의 수강신청, 수강 상태, 재수강 여부 관리
- 수강신청별 성적 부여 및 학생별 성적표 조회
- 단과대학별 공식 공개 학과 목록과 학과 수 조회
- View, Stored Procedure, Transaction, Index 기반 고급 기능 구현
- CSV 기반 대용량 더미 데이터 적재 및 인덱스 최적화 실험
- 실제 학생 개인정보, 실제 학번, 실제 수강신청 내역, 실제 성적 데이터는 관리 범위에서 제외

## 3. 개체 식별

요구사항에 맞추어 개체는 총 6개로 제한하였다. 강한 개체 4개와 약한 개체 2개로 구성한다.
각 개체는 외래키 삽입 전 기준으로 3개 이상 5개 이하의 고유 속성을 가진다.

### 3.1 강한 개체

| 번호 | 개체 | 한글명 | 설명 |
| --- | --- | --- | --- |
| E1 | Student | 학생 | 전남대학교에 소속된 학생. 학번으로 식별한다. |
| E2 | Dept | 학과 | 학생과 교수가 소속되는 학과. 공식 공개 학과 데이터가 반영된다. |
| E3 | Professor | 교수 | 강의를 담당하고 학생을 지도하는 교수. |
| E4 | Lecture | 강의 | 학기마다 개설되는 강의 또는 분반. |

### 3.2 약한 개체

| 번호 | 개체 | 한글명 | 설명 |
| --- | --- | --- | --- |
| E5 | Enrollment | 수강신청 | 학생과 강의가 존재해야 성립하는 약한 개체이며, Student-Lecture M:N 관계를 해소한다. |
| E6 | Grade | 성적 | 수강신청이 존재해야 부여될 수 있는 약한 개체이다. |

## 4. 개체별 속성

### 4.1 Student

| email | 이메일 | UNIQUE |
| office | 연구실 | 임의 생성 데이터 |
| deptid | 소속 학과 | FK |

### 4.4 Lecture

| 속성 | 의미 | 비고 |
| --- | --- | --- |

| lnum | 학수번호/분반 | 예: CSE301, JNU0001 |
| credit | 학점 | 1~3 |

| 속성 | 의미 | 비고 |

## 5. 관계 및 관계대응수

| 번호 | 관계명 | 참여 개체 | 의미 | 관계대응수 | 최소 관계대응수 | 구현 |
| --- | --- | --- | --- | --- | --- | --- |
| R1 | belong | Student-Dept | 학생은 한 학과에 소속된다. | N:1 | Student(1,1), Dept(0,N) | Student.deptid |
| R2 | work_dept | Professor-Dept | 교수는 한 학과에서 근무한다. | N:1 | Professor(1,1), Dept(0,N) | Professor.deptid |
| R3 | tutor | Professor-Student | 교수는 여러 학생을 지도할 수 있다. | 1:N | Professor(0,N), Student(0,1) | Student.advisor_pid |
| R4 | manage | Professor-Lecture | 교수는 여러 강의를 담당한다. | 1:N | Professor(0,N), Lecture(1,1) | Lecture.pid |
| R5 | study | Student-Lecture | 학생은 여러 강의를 수강하고, 강의에는 여러 학생이 참여한다. | M:N | Student(0,N), Lecture(1,N) | Enrollment |
| R6 | evaluate | Enrollment-Grade | 하나의 수강신청에는 최대 하나의 성적이 부여된다. | 1:1 | Enrollment(0,1), Grade(1,1) | Grade.enrollid UNIQUE |

`(최소, 최대)` 표기는 각 개체가 관계에 참여해야 하는 최소·최대 횟수를 의미한다.
예를 들어 Student(1,1)은 학생이 반드시 하나의 학과에 속해야 함을 의미하고, Dept(0,N)은 학생이
없는 학과도 존재할 수 있음을 의미한다.

## 6. 참여 제약

| 관계 | 개체 | 참여 유형 | 구현 근거 |
| --- | --- | --- | --- |
| R1 | Student | 전체 참여 | `deptid NOT NULL` |
| R1 | Dept | 부분 참여 | 학생이 없는 학과 가능 |
| R2 | Professor | 전체 참여 | `deptid NOT NULL` |
| R2 | Dept | 부분 참여 | 교수가 없는 학과 가능 |
| R3 | Student | 부분 참여 | 지도교수 미배정 가능, `advisor_pid NULL` |
| R3 | Professor | 부분 참여 | 지도학생이 없는 교수 가능 |
| R4 | Lecture | 전체 참여 | `pid NOT NULL` |
| R4 | Professor | 부분 참여 | 담당 강의가 없는 교수 가능 |
| R5 | Enrollment | 전체 참여 | `stuid`, `lid` 모두 NOT NULL |
| R6 | Grade | 전체 참여 | `enrollid NOT NULL` |
| R6 | Enrollment | 부분 참여 | 아직 성적이 없는 수강신청 가능 |

## 7. 업무 규칙

| 번호 | 업무 규칙 | 구현 |
| --- | --- | --- |
| BR1 | 학번, 교번, 학과번호, 강의번호, 수강신청ID, 성적ID는 유일하다. | PK |
| BR2 | 학생과 교수는 존재하는 학과에만 소속된다. | FK, NOT NULL |
| BR3 | 강의는 존재하는 교수가 담당한다. | FK, NOT NULL |
| BR4 | 한 학생은 같은 학기에 같은 강의를 중복 신청할 수 없다. | UNIQUE(stuid,lid,semester) |
| BR5 | 수강신청 상태는 수강중/취소/완료 중 하나이다. | ENUM |
| BR6 | 신청 구분은 정규/재수강 중 하나이다. | ENUM |
| BR7 | 성적 점수는 0~100 범위이다. | CHECK |
| BR8 | 하나의 수강신청에는 최대 하나의 성적만 존재한다. | UNIQUE(enrollid) |
| BR9 | 학생 또는 강의가 삭제되면 관련 수강신청과 성적도 함께 삭제된다. | ON DELETE CASCADE |
| BR10 | 학점은 1~3 범위이다. | CHECK |
| BR11 | 공식 공개 학과 데이터는 공개 학과명·단과대학명·전화번호만 사용한다. | jnu_public_seed.sql |
| BR12 | 대용량 성능 실험의 학생·수강·성적은 실제 개인정보가 아닌 CSV 더미 데이터이다. | generate_large_dummy_csv.py |
