## 1. 문서 목적 및 범위

이 문서는 전남대학교(Chonnam University)의 수강신청 및 성적관리 정보를 저장하고 관리하기 위한
데이터베이스의 요구사항 지시서이다. 관리자가 이상 현상 없이 학생·학과·교수·강의 정보를 저장하고
수강신청과 성적 데이터를 조작할 수 있도록 설계한다.

## 2. Chonnam University DB 개요

(요소당 2점, 모두 만족 시 10점 부여)

### 2.1 Chonnam University DB 정의

[요소1] 해당 프로젝트를 통해 하고자 하는 것

본 프로젝트는 대학의 수강신청·성적관리 업무를 데이터베이스로 구현한다. 학생은 매 학기 강의를
수강신청하고, 교수는 강의를 담당하며, 학기 종료 시 수강한 강의에 성적이 부여된다. 파일 기반
관리에서 발생하는 데이터 중복·갱신 이상·참조 무결성 훼손 문제를 막기 위해, 정보를 개체별로
나누어 저장하고 개체 간 관계를 외래키로 연결한 관계형 데이터베이스를 설계하는 것이 목적이다.

### 2.2 Chonnam University DB의 요구사항 지시서

[요소2] 각 개체가 가진 속성 서술 / [요소3] 강한 개체·약한 개체의 적절한 사용

[요소4] 개체 간 관계, 관계대응수와 최소값 서술

[요소5] 개체 4~6개, 각 개체 속성 3~5개(외래키 삽입 이전 기준)

▣ 개체(Entity) — E-1~E-4는 강한 개체, E-5~E-6은 약한 개체

| no | 설명 |
| --- | --- |
| E-1 | 학생(Student)은 학번(stuid), 이름(sname), 학년(stu_year), 연락처(phone), 이메일(email)을 가진다. 【강한 개체】 |
| E-2 | 학과(Dept)는 학과코드(deptid), 학과명(dname), 단과대학(college), 사무실(office), 전화(tel)를 가진다. 【강한 개체】 |
| E-3 | 강의(Lecture)는 강의번호(lid), 강의명(lname), 학수번호(lnum), 학점(credit), 학기(semester)를 가진다. 【강한 개체】 |
| E-4 | 교수(Professor)는 교번(pid), 이름(pname), 직급(prof_rank), 이메일(email), 연구실(office)을 가진다. 【강한 개체】 |
| E-5 | 수강신청(Enrollment)은 신청ID(enrollid), 신청일(enroll_date), 상태(status), 학기(semester), 신청구분(enroll_type)을 가진다. 학생과 강의가 존재해야만 성립하는 【약한 개체】이다. |
| E-6 | 성적(Grade)은 성적ID(gradeid), 점수(score), 등급(grade_letter), 평가일(evaluation_date), 비고(remark)를 가진다. 수강신청이 존재해야만 성립하는 【약한 개체】이다. |

※ 강한 개체는 혼자서 존재 의미가 있는 개체(학생·학과·강의·교수)이고, 약한 개체는 다른 개체가
존재해야만 성립하는 개체(수강신청·성적)이다.

▣ 관계(Relationship) — 관계명 / 관계대응수 / 최소참여(최소값)

| no | 설명 |
| --- | --- |
| R-7 | belong(소속): 모든 학생은 반드시 최소 하나의 학과에 소속되어야 하며, 학생이 한 명도 소속되지 않은 학과는 존재할 수 있다. (학생 N : 1 학과) |
| R-8 | work_dept(근무): 모든 교수는 반드시 최소 하나의 학과에서 근무하며, 교수가 한 명도 근무하지 않는 학과는 존재할 수 있다. (교수 N : 1 학과) |
| R-9 | tutor(지도): 한 명의 교수는 여러 학생을 지도하거나 아무도 지도하지 않을 수 있고, 모든 학생이 지도교수를 가지지는 않아도 된다. (교수 1 : N 학생) |
| R-10 | manage(담당): 강의는 반드시 한 명의 교수가 담당하며, 아무 강의도 담당하지 않는 교수가 있을 수 있다. (교수 1 : N 강의) |
| R-11 | study(수강): 학생은 여러 강의를 수강하거나 하나도 수강하지 않을 수 있고, 강의는 반드시 한 명 이상의 학생이 있어야 진행된다. (학생 M : N 강의) |
| R-12 | evaluate(평가): 하나의 수강신청에는 최대 하나의 성적이 부여되며, 아직 성적이 부여되지 않은 수강신청도 있을 수 있다. (수강신청 1 : 1 성적) |

※ 최소값(최소참여): "반드시 참여"는 전체 참여(예: 학생은 반드시 학과에 소속), "선택"은 부분 참여
(예: 지도교수는 없어도 됨)를 의미한다. 위 관계대응수 및 최소참여는 문서 2의 ER 다이어그램에도
동일하게 표기한다.

▣ 개체·속성 수 제한 충족 [요소5]
개체는 총 6개(강한 개체 4 + 약한 개체 2)이며, 각 개체는 외래키 삽입 이전 기준으로 고유 속성을
5개씩 가진다. 따라서 "개체 4~6개, 각 개체 속성 3~5개" 조건을 모두 만족한다.

E-1부터 E-6까지는 개체에 대한 내용이고, R-7부터 R-12까지는 개체 간의 관계에 대한 내용이다.
